# MeteoBridge · ERA5

Потоковая карта почасовых крупномасштабных осадков (LSP) из исходных NetCDF
двух архивов: Amazon S3 / NCAR ERA5 и Google ARCO-ERA5.
Сервер, чтение файлов, предзагрузка и скачивание архива работают на C#;
интерфейс — HTML/JavaScript. Python для работы сайта не запускается.

## Запуск

- **Visual Studio 2026:** откройте `MeteoBridge.sln`, выберите `MeteoBridge.Era5`, F5.
- **PowerShell:** `./start_app.ps1`, затем адрес из консоли (обычно порт 8766).
- **Данные:** `data/era5`; внешний архив — `./start_app.ps1 -Data 'D:\ERA5'`.
- **На сайте:** «Карта» и «Архив ERA5» с периодами файлов, докачкой и отметкой «Скачано».
- **Скачать через сайт:** в «Скачать данные для карты» выберите Amazon или Google.
  Оба источника сохраняются в исходном `.nc` без изменения содержимого.
  Google NetCDF читается напрямую; его почасовые кадры проигрываются на карте.
  Под выбором архива размещена ссылка на выбранное хранилище.
- **Удаление:** кнопки «Удалить» есть у скачанных файлов и в списке локальных файлов.
  После подтверждения файл удаляется с диска, индекс и кеш карты обновляются.
- **Свои файлы:** в разделе загрузки выберите несколько файлов или перетащите их.
  При ручном импорте GeoTIFF укажите первый час UTC, единицы и тип накопления; для GRIB это
  также можно сделать вручную, если метаданных недостаточно. Кнопка «Добавить все»
  загружает выбранные файлы. Дополнительно читаются GRIB и GeoTIFF через GDAL из NuGet.

Карта объединяет все файлы по часам и ячейкам с приоритетом **NetCDF → GRIB → GeoTIFF**.
Географические сетки и проекции приводятся к общей сетке WGS84, время — к UTC,
осадки — к миллиметрам за час. Нулевые значения сохраняются; непокрытые ячейки
остаются пустыми. Суммарные осадки и другие величины не смешиваются с LSP.
В верхней строке карты между «Осадки · LSP» и кнопками PNG/JPEG
указаны имена и форматы источников: «Кадры файла: …».
В правом верхнем углу карты доступны сохранение PNG и JPEG.
Плавная смена файлов включена автоматически: это эффект воспроизведения, а при
перемотке и на паузе показываются точные значения часа.
Время кадра указано рядом с ползунком. Кнопка справа в строке управления
разворачивает карту вместе с управлением на весь экран; Esc возвращает обычный вид.

Карта занимает всю доступную ширину без искажения пропорций. Управление находится
под картой; перемотка во время воспроизведения продолжает анимацию с выбранного часа.

Нужны .NET 10 SDK, PowerShell 7+ для скриптов и локальные библиотеки в `runtime`.
На этой машине они уже подготовлены. На новой Windows-машине:

```powershell
uv sync --frozen --no-dev
.\scripts\setup_runtime.ps1
.\start_app.ps1
```

Подготовка копирует NetCDF-C и Plotly.js из окружения разработки. После этого
основной сайт читает только `runtime`/сборку, без обращения к `.venv`.

## Структура

| Папка | Что в ней |
| --- | --- |
| `dotnet` | Рабочий C#-сервер, обработка ERA5 и загрузки NCAR |
| `web` | HTML/JavaScript карты и архива, геометрия суши |
| `data/era5` | Реальные исходные NetCDF; не удалять как кэш |
| `runtime` | Локальные нативные библиотеки и Plotly.js |
| `tests`, `scripts` | Проверки текущего сайта и инструменты обслуживания |
| `docs` | Актуальная документация |
| `artifacts` | Проверки текущего сайта, локальные журналы и публикации |

В Visual Studio файлы сгруппированы по назначению.
Все ссылки ведут на настоящие файлы. После добавления/переноса файлов:
`./scripts/update_solution.ps1`. Открывайте `.sln`, не только `.csproj`.

`.venv`, `pyproject.toml`, `uv.lock` — инструменты разработки и тестирования,
а не Python-оболочка сайта. Git и CI сохранены. Кэши IDE/сборки можно пересоздать.
Старый исследовательский проект, его CLI и Streamlit удалены.
Для проверок: `uv sync --frozen`, сборка Release, затем `uv run --frozen pytest`.
Тесты не импортируют старый Python-ридер: результат C# сравнивается с известными
значениями маленьких контрольных NetCDF, созданных только на время проверки.
