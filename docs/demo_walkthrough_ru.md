# Как показать MeteoBridge преподавателю и читать его JSON

Памятка для текущего интерфейса. Проверка примеров: 2026-10-22.
Начните с разделов 1–3; словарь JSON нужен для вопросов после демонстрации.
Все учебные числа ниже проверены текущим solver и certificate checker.
Проверка интерфейса в этот день ограничена чтением его кода: новый browser run
в рамках подготовки памятки не выполнялся.

## 1. Что сказать перед запуском

«В метеоархиве могут быть суммы за пересекающиеся интервалы, неоднозначные
временные метки и слишком крупная временная детализация. MeteoBridge отвечает
на запрос: сколько осадков было за выбранный интервал и насколько точно это
можно установить. Система выдаёт границы, объясняет неоднозначность или конфликт
и оценивает полезность дополнительной информации».

Запрос — это вопрос к уже имеющимся данным. Пример: «Сколько выпало с 00 до 18 часов?».
Это не предсказание завтрашней погоды. Допустимые сценарии — математически
совместимые с записями распределения; ни один из них не объявляется фактически
наблюдавшимся без дополнительных сведений.

Для основных примеров большие данные и интернет не нужны:

```powershell
uv sync --frozen
uv run streamlit run ui/app.py --server.address 127.0.0.1
```

Откройте адрес из терминала. Слева выберите **«Данные → Offline demo»**.
Список **«Случай»** содержит подготовленные учебные задачи.

Встроенные случаи создаются функцией `fixture` в `src/meteo_bridge/fixtures.py`.
Их сохранённые варианты находятся в `data/fixtures/*.json`.
При выборе Offline demo интерфейс использует функцию, а не перечитывает эти файлы.

## 2. Словарь названий встроенных примеров

| Название | Перевод и смысл | Ожидаемый результат при исходных параметрах |
|---|---|---|
| `overlap-exact` | Перекрытие интервалов, точный ответ | 18 мм, `certified` |
| `overlap-bounded` | Перекрытие интервалов, исходные значения заданы диапазонами | [17,7; 18,3] мм, `insufficient_data` при eps=0 |
| `threshold-true` | Проверить достижение порога; ответ положительный | Количество ≥15 мм: `true`, `certified` |
| `threshold-unknown` | Проверить порог; информации недостаточно | Количество ≥18 мм: `null`, `insufficient_data` |
| `daily-total` | Суточная сумма; запрос тоже за сутки | 12 мм, `certified` |
| `insufficient-data` | Не хватает временной детализации | [0; 12] мм за первую половину суток |
| `metadata-label` | Неясно, что означает временная метка | Диапазон [2; 5] мм, `needs_evidence` |
| `conflict` | Несовместимые наблюдения | `inconsistent_model` |
| `unbounded` | Нет наблюдений, ограничивающих сумму сверху | [0; +∞), `insufficient_data` |
| `incomplete-h` | Неполный список трактовок метаданных | `incomplete_model`, даже если перечисленная ветка даёт одно число |
| `cumulative` | Значения накоплены с общего момента сброса | За второй час 5−2=3 мм, `certified` |

`overlap` означает «перекрытие», `exact` — «точный», `bounded` — «ограниченный
границами», `threshold` — «порог», `cumulative` — «накопленный».
Это названия учебных ситуаций; это не названия погодных моделей или методов статьи.

## 3. Показ по шагам: примерно 12–15 минут

### Шаг 1. Точный ответ из перекрывающихся интервалов

Выберите **`overlap-exact`**. В блоке «Наблюдения, метаданные и provenance»
найдите три записи. Они означают:

```text
00          06          12          18 часов
|-----------|-----------|-----------|
|<------ a: 10 мм ------>|
            |<------ b: 12 мм ------>|
            |<- c: 4 -->|
```

Запрашивается сумма за 00–18 часов. Если просто сложить a и b, участок 06–12
будет учтён дважды. Поэтому ответ равен **10+12−4=18 мм**.

В блоке «Ответ» покажите:

- статус `certified`;
- границы [18; 18];
- точечный ответ 18;
- проверку сертификата `valid: true`.

Скажите: «Система объединила ограничения на пересекающиеся интервалы и получила
однозначный ответ». Для доказательства верхней границы в графе используется
путь `00 → 12 → 06 → 18` с весом `10−4+12=18`; обратный путь подтверждает
нижнюю границу 18.

### Шаг 2. Диапазон вместо произвольного числа

Выберите **`overlap-bounded`**. Теперь исходные записи допускают интервалы:

- a: 9,9–10,1 мм;
- b: 11,9–12,1 мм;
- c: 3,9–4,1 мм.

Ответ — **[17,7; 18,3] мм**. При исходном `eps=0` нужен точный ответ, поэтому
статус `insufficient_data`. Это согласованный диапазон, а не конфликт.

Покажите два witness ряда: допустимые распределения, дающие разные результаты.
Линии в Streamlit показывают накопление C(t), а рёбра внутреннего графа
ограничений записаны в сертификате. Линия между двумя узлами не восстанавливает
реальный ход дождя внутри интервала.

Дополнительно в Query поставьте **«Допуск, mm» = `0.3`** и нажмите «Вычислить».
Границы останутся прежними, но ответ **18 ±0,3 мм** уже достаточен: статус
`certified`. Сведения не изменились; изменилось требование к точности.

Если нужно объяснить пороги: `threshold-true` проверяет сумму ≥15 мм. Даже
нижняя граница 17,7 больше 15, поэтому ответ true. В `threshold-unknown`
порог равен 18; диапазон пересекает его, поэтому решение неизвестно.

### Шаг 3. Недостаток детализации и добавление полезного наблюдения

Выберите **`insufficient-data`**. Имеется 12 мм за сутки, а вопрос — о первых
12 часах. Ответ **[0; 12] мм**: весь дождь мог выпасть утром либо позже.
Вопрос о уже известных метаданных не добавляет недостающее измерение.

Раскройте **«Добавить подтверждённое наблюдение той же серии»** и вставьте:

```json
{
  "id": "morning-confirmed",
  "lower": "5",
  "upper": "5",
  "interval": {
    "start": 0,
    "end": 43200,
    "unit": "mm",
    "statistic": "amount"
  },
  "qc": "accepted"
}
```

Нажмите **«Добавить evidence»**. Результат станет **[5; 5] мм**, статус —
`certified`, revision увеличится. Для этой учебной серии пропущенное поле
`series` получает подходящее значение по умолчанию; для реальных данных
нужно явно сохранять полную идентичность серии.

Скажите: «В демонстрации мы ввели условный подтверждённый ответ. В рабочей
задаче он должен поступить из подходящего источника. После добавления новых
ограничений программа пересчитала ответ».

Это показывает также работу с дополнением из другого файла: его совместимые
наблюдения нужно включить в модель. Само наличие файла на диске ничего не добавляет.

### Шаг 4. Уточнение метаданных

Выберите **`metadata-label`**. Здесь заданы две учебные трактовки записей.
В одной сумма за первый час равна 2 мм, в другой — 5 мм. Ответ [2; 5] —
охватывающий диапазон; в этом примере возможны именно два значения, 2 и 5.

В «Следующая информация» выберите **«Подтвердить label» → `end`** и нажмите
**«Сохранить evidence: label»**. Получится **2 мм**. Если начать пример заново
и подтвердить `begin`, получится **5 мм**.

Скажите: «Здесь помогает документация о смысле временной метки. В предыдущем
примере документации недостаточно: требуется дополнительное наблюдение».
Подтверждение в демо задаёт показывающий; программа не устанавливает его сама.

### Шаг 5. Конфликт и неполная модель

Выберите **`conflict`**. В учебных данных за сутки записано 3 мм, а за первую
половину — 4 мм. При неотрицательных осадках это невозможно. В обосновании
есть отрицательный цикл с суммой `3+0−4=−1`.

Скажите: «Не существует ни одного распределения, совместимого с этими
ограничениями. Сертификат указывает конфликтующую группу, но автоматически
не определяет, какая запись ошибочна».

Затем кратко покажите **`incomplete-h`**. В нём перечисленная трактовка даёт
[2; 2], но `h_complete=false`, поэтому итог `incomplete_model`. Узкая граница
не доказывает полноту рассмотренных трактовок. `checker.valid=true` здесь
подтверждает правильность условного расчёта и отказа выдавать полный ответ.

### Шаг 6. Исследовательская часть: какое измерение поможет

Вернитесь к **`insufficient-data`** через другой пример, чтобы начать без
добавленного на шаге 3 наблюдения. В Query установите `amount`, **eps=`0.5`**
и нажмите «Вычислить». Вопрос: получить сумму за первую половину суток с
гарантированной абсолютной ошибкой не более 0,5 мм.

Раскройте **«Оценить дополнительное измерение по всем допустимым рядам»**.
В поле **Actions JSON** вставьте:

```json
[
  {
    "id": "evening",
    "kind": "interval",
    "start": 43200,
    "end": 86400,
    "cost": "1"
  },
  {
    "id": "repeat-day",
    "kind": "interval",
    "start": 0,
    "end": 86400,
    "cost": "1"
  }
]
```

Это два возможных действия: получить сумму за вторую половину или повторно
получить суточную сумму. Здесь нет скрытых ответов: задано только что измерять
и с какой условной стоимостью.

В поле погрешностей оставьте **`0,0.1,0.5,1`**: запятые разделяют числа,
десятичная часть пишется через точку. Нажмите
**«Определить достаточную точность измерения»**.

Ожидается:

| Действие | radius_kind | radius_supremum | safe_at_supremum | Значение |
|---|---|---|---|---|
| `evening` | finite | 1/2 | true | Измерение второй половины достаточно при погрешности ≤0,5 мм |
| `repeat-day` | empty | служебное значение | false | Повтор суточной суммы не обеспечивает нужный ответ даже без ошибки |

Сначала читайте `radius_kind`: при `empty` число в `radius_supremum` не является
допустимой погрешностью. При `finite` это верхний предел; `safe_at_supremum`
показывает, включён ли он. При `unbounded` конечного предела не требуется в модели.

Раскройте результаты для отдельных погрешностей. Для `evening`:

| Ошибка нового измерения ±η | Максимальная оставшаяся ширина ответа | Достаточно для eps=0,5? |
|---:|---:|---|
| 0 мм | 0 мм | Да |
| 0,1 мм | 0,2 мм | Да |
| 0,5 мм | 1 мм | Да |
| 1 мм | 2 мм | Нет |

Для `repeat-day` ширина остаётся 12 мм. Скажите: «Метод заранее оценивает
действия при любом допустимом ответе и вычисляет требования к точности одного
дополнительного измерения. Само измерение пока не выполнено».

Таблица отдельных η — иллюстрация. Сертификат профиля проверяет весь диапазон
конечных η≥0, а не только четыре введённых числа. Обоснование условно
относительно входной модели, полноты H и принятой границы ошибки измерения.

### Шаг 7. Настоящие данные и карта

В **«Данные → Локальный файл»** загрузите
`defense/examples/native_resolution_case.json`. Это реальные encoded
почасовые количества ERA5 LSP для одной точки и одного цикла; все 12 часов
сохранены. Запрос — за первые полчаса. В выбранном примере получится примерно
**[0; 2,128601] мм**. Точная получасовая раскладка из часовых сумм не следует.

Этот пример выбран для наглядности по максимальной ширине после анализа;
полный эксперимент включает все 72 случая. Истинная получасовая сумма неизвестна.
LSP — крупномасштабная компонента осадков, а не total precipitation.

Если карта подготовлена, откройте:

<http://127.0.0.1:8765/synthetic_global_animation.html?view=10gb>

Выберите период, нажмите Play/Pause, приблизьте регион и верните весь мир.
Объясните: «Карта визуализирует глобальную синтетику V2 из ERA5 LSP и показывает
чтение большого архива по кадрам. Графовый метод отдельно работает с ограниченной
задачей одной физической серии. Каждые 12 часов синтетики начинается независимый
эпизод; это не непрерывный прогноз».

На защите не нужно ждать генерации или полного scan 200 ГБ: показывайте заранее
сохранённые результаты и их ограничения. Без больших данных можно показать
основные примеры, реальный компактный case и `defense/experiment_figures.html`.

## 4. Что означает каждый основной JSON-файл

JSON — текстовый формат записи объектов. Само расширение не означает
«метеоданные»: назначение определяется полями файла.

| Файл | Что в нём | Как использовать |
|---|---|---|
| `case.json` | Условия задачи: наблюдения, трактовки, запрос и допущения | Повторно загрузить задачу |
| `result.json` | Итог: статус, границы, ответ, причины, сценарии и предложения | Читать результат |
| `certificate.json` | Проверяемое обоснование результата | Передать checker вместе с case/result |
| `report.json` | Case, result, certificate, checker и метрики в одном объекте | Сохранить полный запуск |
| `actions.json` | Кандидаты получения новой информации и их стоимости | Подать модулю оценки действий |
| `acquisition.json` | Оценки действий при точном ответе о количестве/метаданных и сертификат | Сравнить оставшуюся неопределённость |
| `precision.json` | Требования к погрешности одного нового интервального измерения и сертификат | Показать исследовательский профиль |
| `manifest.json` большого набора | Перечень data files, размеры, checksums, конфигурация | Найти и проверить части архива; сами миллионы значений находятся в `.nc` |
| `run.json` эксперимента | Протокол, записи запусков, измеренные результаты и ошибки | Проверить, что фактически было выполнено |
| `scale_report.json` | Размеры, scan, throughput, память и Query checks большого архива | Показать нагрузочные испытания |
| JSON рядом с HTML карты | Источник, семантика, область, хеши и параметры построения | Проверить происхождение визуализации |

В Streamlit в «Экспорт» кнопки `case.json`, `result.json`, `certificate.json`
и `report.json` создают эти документы из текущей задачи. В CLI они сохраняются
в каталоге `--output`. Имена `overlap-exact.json`, `conflict.json` и другие
из `data/fixtures/` — это Case JSON, названные по учебным ситуациям.

### Входной Case JSON: что читать в первую очередь

| Поле | Простыми словами |
|---|---|
| `id` | Название/идентификатор задачи |
| `observations` | Список исходных наблюдений |
| `hypotheses` | Список допустимых трактовок метаданных H |
| `query` | Вопрос, на который нужно ответить |
| `h_complete` | Заявлена ли полнота перечисленных трактовок в указанной области |
| `completeness_basis` | На чём основано заявление о полноте |
| `assumptions` | Допущения, например неотрицательность осадков |
| `revision` | Версия задачи после добавления evidence |
| `evidence` | История добавленных подтверждений |
| `family_id` | Семейство задачи для группировки экспериментов |
| `origin` | `synthetic`: искусственная; `controlled`: с контролируемыми преобразованиями; `original`: исходная |
| `source_manifests` | Источники, версии, лицензии, параметры получения и хеши |

Внутри **одного наблюдения**:

| Поле | Значение |
|---|---|
| `id` | Идентификатор записи, например a |
| `series` | К какой физической серии относится запись |
| `original_value`, `original_timestamp` | Исходное представление значения и метки, если сохранено |
| `lower`, `upper` | Допустимые нижняя и верхняя границы значения; равенство означает точное encoded значение |
| `interval.start`, `interval.end` | Начало и конец интервала |
| `interval.unit` | Единицы: например mm или mm/h |
| `interval.statistic` | `amount`: количество; `cumulative`: накопление; `interval_mean_rate`: средняя интенсивность |
| `interval.reset_start` | Документированный момент начала накопления для cumulative |
| `qc` | `accepted`: используется; `missing`: пропуск; `rejected`: отвергнуто |
| `reset_group` | Группа сброса накопления, согласованная с циклом серии |
| `evidence_ids` | Ссылки на обосновывающие сведения |

`instantaneous_rate` означает мгновенную интенсивность; текущая модель не
превращает её в количество за интервал без дополнительной модели.

**SeriesKey** защищает от смешивания разных рядов. В ней `quantity` — величина,
`location` — место, `spatial_support` — пространственная область/точка,
`product` и `version` — продукт и версия, `member` — участник ансамбля/сценарий,
`vertical_support` — вертикальная привязка, `cycle` — цикл инициализации/накопления.
Одинаковое время у разных станций или cycles не делает их одной точной функцией.

Внутри **гипотезы** `id` называет вариант, `assignments` задаёт значения
метаданных, а `intervals` переопределяет интерпретацию конкретных observations
для этой ветки. Пустой `intervals` означает использование интервалов самих записей.
`evidence_ids`, `assumptions`, `compiler_version`, `completeness_scope`
сохраняют обоснование, допущения, версию преобразования и область полноты.
`H=1` не означает единственного почасового распределения: внутри одной
трактовки может оставаться бесконечно много допустимых распределений.

Внутри **Query**:

| Поле | Значение |
|---|---|
| `series` | Какая физическая серия нужна |
| `start`, `end` | За какой интервал спрашиваем |
| `objective` | `amount`: количество; `threshold`: ответить на вопрос «количество ≥ порога?» |
| `eps` | Допустимая абсолютная ошибка ответа в mm; 0 требует точного количества |
| `threshold` | Порог для threshold Query |
| `unit` | Единицы ответа, сейчас mm |
| `timezone`, `calendar` | Временная система |
| `permitted_assumptions` | Поле контракта для разрешённых допущений; не включает автоматическое восстановление дождя |

Числа start/end в JSON — секунды Unix UTC. В учебных примерах за начало
принято `1970-01-01T00:00:00+00:00`, поэтому интерфейс показывает 1970 год:

| Число | Время относительно учебного начала |
|---:|---|
| 0 | 00:00 |
| 21600 | 06:00 |
| 43200 | 12:00 |
| 64800 | 18:00 |
| 86400 | 00:00 следующих суток |

Это временная шкала математического примера, а не реальные измерения 1970 года.

### Ответ result.json

| Поле | Значение |
|---|---|
| `status` | Достаточность ответа, конфликт или ограничение модели |
| `lower`, `upper` | Обоснованные границы количества |
| `bound_kind` | Для каждой границы: finite, unbounded или empty |
| `point_estimate` | Середина диапазона, если он достаточно узок для eps; не вероятностный прогноз |
| `decision` | Для порога: true, false или null=не установлено |
| `reason_flags` | Причины: temporal_underdetermination, metadata_ambiguity, missing_bounds, conflict |
| `witnesses` | Допустимые ряды с различающимися ответами |
| `suggested_actions` | Тип дополнительной информации; доступность наблюдения не предполагается автоматически |
| `scope`, `h_complete`, `completeness_basis`, `assumptions` | Область и условия вывода |
| `case_id`, `revision`, `case_hash`, `certificate_id` | Связь с задачей, её версией и сертификатом |
| `unit` | Единицы |

`certified` при amount означает ширину ≤2·eps и полноту заявленной модели.
При eps=0 это точный ответ. При threshold он означает установленную сторону
порога, даже если само количество остаётся диапазоном.

`needs_evidence` указывает, что трактовки дают разные границы; это не обещание,
что любой вопрос о метаданных полностью разрешит задачу. Дополнительная
неопределённость внутри ветвей тоже может сохраниться.

`incomplete_model` также может сопровождать исчерпание рабочего бюджета/таймаут:
читайте `error` и условия H. `unsupported` — неподдерживаемый вход;
`execution_failed` — ошибка выполнения. Эти состояния не доказывают
физическую нехватку наблюдений.

### Сертификат certificate.json и проверка

`normalized_constraints` — рёбра графа для каждой трактовки. У ребра:

- `u` — откуда идёт ребро, время в UTC seconds;
- `v` — куда;
- `w` — вес; утверждение C(v)−C(u)≤w;
- `id` — идентификатор ограничения, по которому записываются пути.

В `worlds` находятся результаты по трактовкам: `feasible` — согласованность,
`lower_path`/`upper_path` — доказательные пути, `lower_point`/`upper_point` —
достигающие границы накопленные ряды. `negative_cycle` показывает конфликт;
направления `*_ray` обосновывают неограниченные границы, если они есть.
Не каждое поле присутствует во всех случаях.

`case_hash`, `query_hash`, `observation_hashes` связывают доказательства с
точным входом. `scope`, `revision`, `assumptions`, `h_complete`, `unit`,
`version`, `numerical_policy` задают область и правила проверки.

`checker.valid=true` означает, что проверка приняла результат и сертификат.
Это совместимо с конфликтом или insufficient_data: корректно обоснованный
отказ дать точное число тоже проверяется. Полнота H и физическая точность
источника сами по себе этим не устанавливаются.

Дроби вроде `177/10` и `1/2` равны 17,7 и 0,5. Рациональные строки сохраняют
точную арифметику модели. `null` означает отсутствие значения, а не ноль:
верхняя граница null с bound_kind=unbounded означает отсутствие конечной
границы; с bound_kind=empty — отсутствие допустимых вариантов.

### Действия и профиль точности

У action поля `id` — название, `kind` — interval или metadata, `start/end` —
интервал измерения, `attribute` — уточняемое поле метаданных, `cost` —
заданная положительная стоимость. Это условная цена сравнения, не измеренное
время HTTP-запроса или рубли. Ответа будущего измерения в action нет.

В `acquisition.json` `worst_remaining_width` — максимальная оставшаяся ширина
после такого точного ответа; `guarantees_resolution` — достаточность для Query
в объявленной модели. Результат оценивает действия, но не исполняет их.

В `precision.json` `eps` относится к ответу на Query, а η — к ошибке нового
измерения. В `result.actions` читайте поля radius_kind, radius_supremum,
safe_at_supremum и conditional_guarantee, как на шаге 6. Во вложенных `values`
показаны ширина и guarantees_resolution для выбранных η. `checker` проверяет
весь профиль; `certificate` хранит обоснования по парам допустимых сценариев.
Профиль поддерживает один interval action и amount Query; несколько действий
не объединяются автоматически в оптимальную стратегию.

## 6. Как закончить выступление

«Графовые ограничения — известный инструмент. Исследовательский кандидат
проекта — специализированное построение проверяемого профиля требований к
точности одного дополнительного измерения при конечных трактовках метаданных.
Есть сохранённые проверки и сравнения с независимым LP и графовыми baselines.
Проверены также реальные значения и обработка большого архива ограниченными
задачами. Мировой приоритет и независимая внешняя проверка пока не установлены».

Если времени мало, покажите overlap-exact, insufficient-data с добавлением
наблюдения, conflict и профиль evening/repeat-day. JSON открывайте для
конкретного объяснения; чтение всего сертификата по строкам для показа не требуется.
