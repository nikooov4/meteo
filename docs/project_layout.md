# Устройство проекта

MeteoBridge запускается через `start_app.ps1` или решение `MeteoBridge.sln`.
C#-сервер предоставляет карту, архив, генерацию и сравнение.
Он управляет дочерними процессами чтения ERA5 и постоянным GPU-процессом GrathCast.
При закрытии сервера GPU-процесс завершается; он также контролирует родительский PID.

## Границы компонентов

- `dotnet/MeteoBridge.Era5`: HTTP API, чтение ERA5, загрузки, приоритеты, индексация,
  общий каталог воспроизведения и управление генерацией.
- `MapPlayback.cs`: временная шкала основной карты и приоритеты архивов ERA5.
- `ArchiveComparison.cs`: выбор ERA5 за период прогноза и суммирование
  почасовых осадков за шестичасовые интервалы для двух карт.
- `dotnet/MeteoBridge.Era5.Tests`: тесты xUnit с локальными HTTP-серверами и
  временными файлами NetCDF, GRIB и GeoTIFF.
- `workers/graphcast`: только используемый код GPU-worker, lock-файл пакетов
  и манифесты проверенных официальных весов и исходников.
- `runtime`: восстановимые сторонние зависимости. В `runtime/graphcast`
  находятся `python`, `.venv-gpu`, `assets`, `vendor`; исходники приложения здесь не лежат.
- `data`: пользовательские данные, подготовленные входы и прогнозы.
- `scripts`: подготовка библиотек и модели; `update_solution.ps1` создаёт ссылки
  Visual Studio на существующие исходники, документы и проверки.

Страницы читаются из `web` при работе в проекте. Подготовленная .NET-сборка содержит
копии HTML, геометрию, Plotly и нативные библиотеки для автономного просмотра ERA5.
Для генерации рядом нужен полный проект с `workers` и подготовленным `runtime/graphcast`.
Пути определяются от корня проекта; GPU-окружение обновляет путь к локальному Python
при переносе всей папки.

## Подготовка и проверки

```powershell
uv sync --frozen
.\scripts\setup_runtime.ps1
.\scripts\setup_graphcast.ps1 -VerifyOnly
.\scripts\update_solution.ps1
dotnet build MeteoBridge.sln -c Release
uv run --frozen ruff check .
dotnet test MeteoBridge.sln -c Release
node --test tests/map_viewer.test.cjs tests/archive_viewer.test.cjs tests/comparison_viewer.test.cjs tests/generation_viewer.test.cjs
```

Обычные тесты используют временные данные и локальные серверы. Проверяются
известные значения NetCDF/GRIB/GeoTIFF, маски, нули, перепроекция, очереди,
приоритеты, восстановление загрузок, удаление, путь импорта и отсутствие загрузки
модели при простом просмотре страниц. Проверки JavaScript выполняются без браузерных
зависимостей и охватывают перемотку, гонки ответов, паузу, полный экран и шаг 6 часов.
Доступ к реальному аккаунту CDS требует пользовательского токена; локальные тесты
не подтверждают доступность внешнего сервиса или права аккаунта.

## Очистка

`data/era5`, `data/graphcast-inputs` и `data/graphcast` — данные, их нельзя считать
кэшем. Прогнозы удаляются из выбранного архива через сайт.
`runtime` нужен для генерации и повторной сборки; восстановление требует подготовки.

Пересоздаются `bin`, `obj`, `.vs`, `.dotnet-home`, кэши uv/Ruff/Python и локальные логи.
Корневая `.venv` нужна для инструментов подготовки и проверки Python-кода. Отдельное CPU-окружение GraphCast, пробные CLI,
дубли NetCDF из экспериментов, старые zip исходников и кэш загрузок убраны.
Маленькие отчёты прежних запусков сохранены в `artifacts/validation` как история;
их число тестов и замеры относятся к состоянию приложения в момент проверки.
