# Генерация GrathCast в основном проекте

Веб-сервер и архивы работают на C#. `GraphCastService` запускает постоянный
Python-worker `workers/graphcast/service.py` только по первому запросу генерации.
Запуск — напрямую в Windows через WinJAX, без WSL2.

## Файлы

- `runtime/graphcast/assets/model.npz` и `*_by_level.nc` — официальные веса и статистика.
- `runtime/graphcast/vendor/upstream-gpu`, `vendor/xarray-jax` — официальные исходники.
- `runtime/graphcast/.venv-gpu` — проверенное GPU-окружение, `python` — локальный Python 3.12.
- `workers/graphcast/gpu_runtime.py` — локальная настройка CUDA: короткие пути Windows,
  отключённые autotuning/Triton GEMM, отсутствие предварительного выделения 75% VRAM.
- `workers/graphcast/requirements.lock.txt` — точные версии, включая WinJAX 0.11.2
  и CUPTI 13.3.75. Установка не изменяет системный драйвер.
- `data/graphcast-inputs` — подготовленные входные файлы и загрузки пользователя.
- `data/graphcast-inputs/.era5` — входы из суточных архивов ERA5, привязанные
  к версии исходного файла. Туда же записывается очередь подготовки.
- `data/graphcast/<UUID>/forecast.nc` — суточный результат; `metadata.json` — описание,
  `frames.bin` — четыре проверенных кадра карты.
- `data/graphcast/.pending` — незавершённые результаты; они не видны в архиве.
- `artifacts/logs/graphcast.log` — stderr постоянного процесса.

В генераторе сохраняется полный исходный выход нейросети. Только для отображения
карты отрицательные осадки ограничиваются нулём. Файл содержит статические поля,
поэтому сам может стать входом для следующего суточного прогноза.

Один запрос создаёт один NetCDF на **1 день (24 часа)**, с шагами +6/+12/+18/+24 часа.
Длина проверяется перед сохранением. `forecast_reference_time` задаёт начало,
`valid_time` — конец каждого шестичасового интервала; `forecast_horizon_hours=24`.
Для подготовки: `./scripts/setup_graphcast.ps1`; проверка без сети/GPU —
`./scripts/setup_graphcast.ps1 -VerifyOnly`.

## Суточный архив и сравнение

На вкладке «Генерация» выберите скачанный глобальный ERA5 с 24 непрерывными
часами покрытия. Во входном списке отображаются готовые файлы. Суточный архив
появляется после подготовки входа для ИИ, а его выбор сразу запускает прогноз.
Начало прогноза совпадает с концом последнего интервала архива.
У почасовых накоплений ERA5 метка времени обозначает конец часа. Например,
файл с метками 00:00–23:00 покрывает период от 23:00 предыдущей даты до 23:00
указанной даты.

При первой загрузке суточного архива сервер ставит подготовку входа в очередь.
В «Архиве» состояние меняется на «Готов для ИИ», когда NetCDF сохранён.
Для ранее скачанных файлов есть кнопка «Подготовить для ИИ». Ожидающие задачи
возобновляются после перезапуска приложения. Готовый вход используется при
следующих генерациях. При повторе незавершённой подготовки используются уже
скачанные поля.

При подготовке сервер суммирует LSP из исходного файла за два последних шестичасовых
интервала на сетке 1°. Он дополняет их почасовыми конвективными осадками и
получает приземные и атмосферные поля для обоих состояний прямым чтением
публичного [Google ARCO-ERA5](https://github.com/google-research/arco-era5#analysis-ready-data).
Доступные даты определяются по метаданным архива, включая опубликованную
предварительную версию ERA5T. Статические поля берутся из подготовленного примера
GraphCast. Для обновления зависимостей окружения запустите `./scripts/setup_graphcast.ps1`.
Подготовка входа выполняется на CPU. Файл прогноза сохраняется после проверки
всех четырёх шагов на GPU.

Вкладка «Сравнение» открывается по `/comparison` или из списка прогнозов.
Выберите сохранённый прогноз и скачанный ERA5, чьё покрытие пересекается с ним.
Обе карты переключаются по одним шестичасовым интервалам. Слева отображается
сумма шести часовых LSP, справа — суммарные осадки модели. Если в архиве
пропущен час или отдельная ячейка, соответствующие данные остаются пустыми.
Основная карта показывает почасовые данные ERA5.

## Входной NetCDF

Поддерживается подготовленный глобальный NetCDF в формате GraphCast. Оси:
`lat` (-90..90, шаг 1°), `lon` (0..359 или -180..179, шаг 1°), `level`, `time`.
Также принимаются имена `latitude`, `longitude`, `pressure_level`.
Уровни, гПа: 50, 100, 150, 200, 250, 300, 400, 500, 600, 700, 850, 925, 1000.

Нужны поля:

- `2m_temperature` (K), `mean_sea_level_pressure` (Pa),
  `10m_u_component_of_wind`, `10m_v_component_of_wind` (м/с),
  `total_precipitation_6hr` (метры за предыдущие 6 часов).
- `temperature` (K), `geopotential` (м²/с²), `u_component_of_wind`,
  `v_component_of_wind` (м/с), `vertical_velocity` (Pa/s),
  `specific_humidity` (кг/кг) на указанных уровнях.
- Статические `geopotential_at_surface` и `land_sea_mask`.

Абсолютное время задаётся `datetime`, `valid_time` или осью `time` datetime64.
Генератор выбирает последнее состояние и состояние ровно за 6 часов до него.
Дата начала и конца прогноза указана в UTC. Суточный горизонт — 24 часа
от последнего входного состояния, он не обязательно совпадает с календарными сутками.
Годовой/суточный ход и входящее солнечное излучение вычисляются из времени и сетки;
будущие погодные поля в модель не передаются.

Контрольный `era5-example-2022-01-01.nc` содержит два официальных входных состояния
ERA5 1 января 2022 года в 00:00 и 06:00 UTC. Готовый входной NetCDF используется
сразу. Суточные LSP из скачанного архива сначала дополняются полями Google ARCO-ERA5.

## Жизненный цикл

Одновременно выполняется одна генерация. Веса загружаются на GPU один раз.
Форма, порядок и относительные координаты входов приводятся к постоянному виду,
чтобы смена суток не вызывала перекомпиляцию. Счётчики загрузок/компиляций и PID
сохраняются в метаданных результата. При завершении приложения worker останавливается;
дополнительный контроль родительского PID освобождает GPU при аварийном закрытии.
Если worker завершается с ошибкой, следующий запрос создаёт новый процесс.

Готовые результаты публикуются атомарным переносом папки из `.pending`.
Удаление обращается только к UUID выбранного архива, удаляет NetCDF, кадры
и метаданные; файл, используемый текущей генерацией, удалить нельзя.

## API

| Метод и путь | Назначение |
| --- | --- |
| GET `/api/graphcast/status` | Состояние, шаг, PID, загрузка модели |
| GET `/api/graphcast/inputs` | Входные файлы и состояние подготовки суточных архивов |
| POST `/api/graphcast/prepare` | Подготовить скачанный архив, JSON `{ "id": "идентификатор архива" }` |
| POST `/api/graphcast/cancel-preparation` | Приостановить подготовку скачанного архива |
| POST `/api/graphcast/import?name=...nc` | Добавить входной файл, тело — исходные байты |
| POST `/api/graphcast/generate` | Начать генерацию, JSON `{ "id": "идентификатор входа" }` |
| GET `/api/graphcast/files` | Все завершённые прогнозы |
| GET `/api/archive/files?source=graphcast&year=0` | Архив GrathCast в общем каталоге |
| GET `/api/graphcast/metadata?id=...` | Описание и сетка прогноза |
| GET `/api/graphcast/frame?id=...&index=0` | Кадр, little-endian float32, 181×360 |
| GET `/api/graphcast/file?id=...` | Скачать NetCDF |
| POST `/api/graphcast/delete` | Удалить прогноз, JSON `{ "id": "UUID" }` |

HTML-страницы: `/`, `/downloads`, `/generation`, `/comparison`.
Сравнение использует `/api/comparison/files`, `/api/comparison/grid` и
`/api/comparison/frame`. Основной проигрыватель читает `/map-playback/all`.

## Проверки

```powershell
dotnet test MeteoBridge.sln -c Release
node --test tests/map_viewer.test.cjs tests/archive_viewer.test.cjs tests/comparison_viewer.test.cjs tests/generation_viewer.test.cjs
```

C#-тесты xUnit проверяют правила суточного входа, выбор часов в Google ARCO-ERA5,
суммирование LSP и совпадение интервалов, сохранённые прогнозы и отделение их
от основной карты. Внешние источники в автоматических проверках заменены
локальными HTTP-серверами.

Для проверки с подготовленной NVIDIA GPU-средой включите тест первого
скачивания архива, подготовки входа из Zarr и генерации после перезапуска с сохранённым входом.

```powershell
$env:METEOBRIDGE_TEST_GPU = '1'
dotnet test MeteoBridge.sln -c Release --filter FullyQualifiedName~GraphCastGpuTests
```
