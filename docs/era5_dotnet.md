# ERA5: потоковая карта на C#

Основной просмотрщик работает с уже имеющимися NCAR ERA5 LSP `.nc`.
Генерация синтетических данных в этом запуске не используется.

## Visual Studio

Откройте `MeteoBridge.sln` в Visual Studio 2026 (18.x), установив workload
«ASP.NET и веб-разработка» и .NET 10 SDK. Выберите `MeteoBridge.Era5` стартовым
проектом и нажмите F5 или Ctrl+F5. Предпочтительный адрес Visual Studio —
`http://127.0.0.1:8767/`; запуск из PowerShell использует 8766.
При занятом порте сервер выбирает следующий и печатает фактический адрес.
Visual Studio открывает браузер уже после успешного запуска с правильным адресом.
Повторный `start_app.ps1` использует работающий экземпляр с той же папкой и числом workers.

В обозревателе решения рабочие файлы сгруппированы по назначению: `Web`, `Tests`,
`Tools`, `Documentation`, `Runtime`, `Validation`. Исследовательский Python-проект,
материалы защиты и ссылки на них удалены по запросу пользователя.
Это ссылки на исходные файлы; изменения сразу действуют в проекте. Открывайте
именно `.sln`, а не только `.csproj`, чтобы видеть всё дерево.

Сервер, индекс и обработчики кадров написаны на C#. Python-процесс для карты
не запускается. На этой машине NetCDF-C с зависимостями и локальный Plotly.js
подготовлены в `runtime` через `scripts/setup_runtime.ps1` и копируются в сборку.
Исходное окружение `.venv`, созданное через `uv sync --frozen`, используется
только при подготовке библиотек и разработке, а не при работе C#-сайта.
NetCDF-C вызывается напрямую через P/Invoke. Дополнительных NuGet-пакетов нет.

Альтернативные библиотеки задаются переменными `METEOBRIDGE_NETCDF_LIBRARY`
(полный путь к NetCDF-C DLL вместе с её зависимостями) и `METEOBRIDGE_PLOTLY_JS`
(полный путь к `plotly.min.js`). При переносе опубликованной сборки передайте
`--root PATH` к каталогу проекта. Поставляемые DLL должны соответствовать x64.

## PowerShell

Из корня проекта:

```powershell
.\start_app.ps1
.\start_app.ps1 -Data 'D:\ERA5' -Workers 3 -Port 8766
```

Путь может вести к одному `.nc` или папке: вложенные папки учитываются.
Остался только C#-сайт. Старый научный интерфейс, параметр `-Python`, CLI `meteo`,
генераторы и Python-ридер удалены. Реальные данные в `data/era5` сохранены.

## Архив и загрузки на сайте

В верхнем меню доступны **Карта** и **Архив ERA5** (`/downloads`).
В архиве выберите год и месяц либо весь год. Каталог читается из публичного
S3 NSF NCAR, с фильтром только на NCAR ERA5 LSP NetCDF. У каждого файла показаны
точные начало и конец в UTC, размер, состояние и кнопка загрузки.
Имеющиеся `.nc` сравниваются с размером удалённого файла и отмечаются **Скачано**.
Наличие файла проверяется на диске, поэтому отметка сохраняется после перезапуска.

Скачивание выполняется на C# в ту же папку, что выбрана в `Era5:Data`;
для пути к одному файлу — рядом с ним. Для отображения всех загруженных файлов
задавайте папку, а не одиночный `.nc`. В очереди до 24 файлов, одновременно
передаются два; учитываются свободный диск, незавершённые задания и резерв 512 MiB.
Размер памяти для сетевого блока — до 4 MiB на загрузку. Можно остановить загрузку
и продолжить её позднее, включая после перезапуска сервера.

Блоки запрашиваются через HTTP Range с If-Match/ETag. `.nc.partial` и
`.download.json` хранят подтверждённый префикс и идентичность удалённого файла.
Готовый файл проверяется через NetCDF-C, затем атомарно переименовывается в `.nc`.
Существующие готовые файлы не перезаписываются. Проверка отметки «Скачано» по размеру
не заменяет научную checksum-проверку всего архива.
После загрузки перейдите обратно на **Карту**: индекс обновляется автоматически.
Доступные промежутки показаны крупным раскрытым блоком над картой;
нажатие на промежуток сразу выбирает его для просмотра.

API загрузок: `GET /api/archive/settings`, `GET /api/archive/files?year=2023&month=0`,
`POST /api/archive/download` и `/cancel` с JSON `{ "key": "ключ из каталога" }`.
URL и пути от браузера не принимаются; загружаются только ключи из прочитанного
каталога. Для тестов доступен `Era5:ArchiveBaseUrl` на loopback HTTP.

## Настройки

В `dotnet/MeteoBridge.Era5/appsettings.json`, секция `Era5`:

| Настройка | По умолчанию | Назначение |
|---|---:|---|
| Data | data/era5 | Путь к реальным данным относительно корня проекта |
| Workers | 2 | Число отдельных процессов чтения, 1–4 |
| LookaheadCycles | 3 | Сколько следующих циклов готовить, 0–6 |
| CacheCycles | 6 | Лимит готовых и ожидающих циклов, 1–12; не меньше LookaheadCycles + 1 |
| MaxCells | 100000 | Максимум отображаемых точек в одном кадре, до 1000000 |
| MaxReadMiB | 256 | Максимальный размер исходного 12-часового float32-блока на worker |
| Bbox | [-180,180,-90,90] | Необязательная область west, east, south, north |

Изменения применяются после перезапуска сервера. Параметры также принимаются
через `--Era5:Workers 3` и другие ключи стандартной конфигурации ASP.NET Core.

## Поток обработки

1. Индексируются только координаты и время всех файлов; поля осадков не сканируются.
2. Первый запрошенный цикл получает приоритет, за ним ставятся три следующих.
3. Два процесса параллельно читают разные циклы. Внутри каждого процесс работает
   с NetCDF последовательно: библиотека NetCDF-C/HDF5 не считается потокобезопасной.
4. Исходный цикл читается одним непрерывным hyperslab, соответствующим native chunk
   текущих NCAR-файлов. Затем выбираются координаты карты, метры переводятся в мм.
   Флаги пропусков, fill values, valid range, отрицательные и нечисловые значения
   становятся NaN. Почасовые amounts не вычитаются друг из друга.
5. В браузер передаётся только один час в little-endian float32. Браузер держит
   до 12 кадров и готовит следующие восемь, выполняя до двух запросов одновременно.
6. При переходе к следующему циклу окно предзагрузки сдвигается даже при попадании
   кадра в кеш браузера. При перемотке браузер отменяет устаревшие запросы, сервер
   отменяет ненужные незавершённые циклы. Занятый отменённым чтением worker
   завершается и при следующем запросе запускается заново.

Архив целиком в память не загружается. При стандартной сетке 181×360 шесть
готовых циклов занимают до 18.8 MB данных в серверном кеше; у каждого worker
дополнительно есть исходный блок (~50 MB), native chunk cache (64 MiB) и .NET runtime.
MaxReadMiB ограничивает один массив, а не полный RSS дерева процессов.
С повышением Workers и MaxCells растёт потребление памяти. Дисковая пропускная
способность и сжатие могут ограничивать выигрыш от дополнительных workers.

Часы между файлами остаются пустыми. Совпадающие часы берутся из первого пути
в порядковой сортировке. Смена размера или mtime исходника отклоняется, включая
обращения к серверному кешу. После изменения файлов перезапустите сервер.
На Windows для native NetCDF с кириллицей используются короткие пути NTFS;
при недоступных коротких именах используйте каталог с ASCII-путём.

API `/map-archive/catalog`, `/range`, `/frame` совместим с прежним viewer.
Дополнительно доступны `/prefetch`, `/metrics`, `/health` и `/grid`.
`end_hour` ограничивает подготовку выбранным периодом, конец не включается.
Идентификатор архива передаётся как `manifest_sha256`. Ошибки выбора дают 422,
смена идентификатора — 409. Сервер предназначен для локального просмотра
и принимает только loopback-соединения.

## Проверки

```powershell
uv sync --frozen
dotnet build MeteoBridge.sln -c Release
uv run --frozen pytest -q -p no:cacheprovider --junitxml=artifacts/validation/site-only-full.xml
uv run --frozen ruff check tests
```

Тесты сами запускают временные C#-серверы и локальный контрольный NCAR-каталог.
Работающий основной сервер и доступ к интернету им не нужны.
Контрольные значения, сетка, интервалы и маски заданы независимо от старого ридера.

## Исторические замеры

На этой машине проверены 48 реальных кадров (3 127 680 значений): float32
и позиции NaN совпали точно. Переходы Python между циклами заняли 2.78–3.03 с,
C# с предзагрузкой — 4.16–8.75 мс; первый кадр C# — 581 мс. Зафиксированы два
одновременных worker и серверный кеш 18 766 080 байт. Это результат данного
запуска с неконтролируемым кешем ОС, не гарантия задержек на другой машине.

Тесты создают маленькие контрольные NetCDF: это тестовые fixtures, а не новый
синтетический набор для визуализации. Проверяются переходы между файлами,
пропуски, маски, дубликаты, изменение исходника, границы выбранного периода,
точность, параллельность и повторное использование кеша.
Дополнительно проверяются занятый порт, повторный запуск, каталог NCAR,
отмена, докачка по Range/ETag, статусы имеющихся файлов и обновление индекса.

До удаления исследовательского проекта полный прогон включал 176 тестов.
Через вкладку сайта скачан реальный
файл `2023011606_2023020106.nc` размером 287 864 531 байт. Статус сменился на
«Скачано», в индексе стало 13 файлов и 4704 часа с данными; кадр за 2023-01-20
успешно прочитан без перезапуска сервера. Подробности и SHA256 сохранены в
`artifacts/validation/era5-download-real.json`.
