# ERA5: потоковая карта на C#

Просмотрщик объединяет NCAR ERA5 LSP `.nc`, GRIB и GeoTIFF с крупномасштабными осадками.
Генерация синтетических данных в этом запуске не используется.

## Visual Studio

Откройте `MeteoBridge.sln` в Visual Studio 2026 (18.x), установив workload
«ASP.NET и веб-разработка» и .NET 10 SDK. Выберите `MeteoBridge.Era5` стартовым
проектом и нажмите F5 или Ctrl+F5. Предпочтительный адрес Visual Studio —
`http://127.0.0.1:8767/`; запуск из PowerShell использует 8766.
При занятом порте сервер выбирает следующий и печатает фактический адрес.
Visual Studio открывает браузер уже после успешного запуска с правильным адресом.
Повторный `start_app.ps1` использует работающий экземпляр с той же папкой и числом workers.

В обозревателе решения рабочие файлы сгруппированы по назначению: `Web`, `Tests`,
`Tools`, `Documentation`, `Runtime`, `Validation`. Исследовательский Python-проект,
материалы защиты и ссылки на них удалены по запросу пользователя.
Это ссылки на исходные файлы; изменения сразу действуют в проекте. Открывайте
именно `.sln`, а не только `.csproj`, чтобы видеть всё дерево.

Сервер, индекс и обработчики кадров написаны на C#. Python-процесс для карты
не запускается. На этой машине NetCDF-C с зависимостями и локальный Plotly.js
подготовлены в `runtime` через `scripts/setup_runtime.ps1` и копируются в сборку.
Исходное окружение `.venv`, созданное через `uv sync --frozen`, используется
только при подготовке библиотек и разработке, а не при работе C#-сайта.
NetCDF-C вызывается напрямую через P/Invoke. GRIB и GeoTIFF читает GDAL:
`MaxRev.Gdal.Core` и соответствующий Windows/Linux x64 runtime, закреплённые
на версии 3.13.3.557. NuGet восстанавливает библиотеки при первой сборке;
после сборки Python и установленный в системе GDAL для сайта не нужны.

Альтернативные библиотеки задаются переменными `METEOBRIDGE_NETCDF_LIBRARY`
(полный путь к NetCDF-C DLL вместе с её зависимостями) и `METEOBRIDGE_PLOTLY_JS`
(полный путь к `plotly.min.js`). При переносе опубликованной сборки передайте
`--root PATH` к каталогу проекта. Поставляемые DLL должны соответствовать x64.

## PowerShell

Из корня проекта:

```powershell
.\start_app.ps1
.\start_app.ps1 -Data 'D:\ERA5' -Workers 3 -Port 8766
```

Путь может вести к одному поддерживаемому файлу или папке: вложенные папки учитываются.
Остался только C#-сайт. Старый научный интерфейс, параметр `-Python`, CLI `meteo`,
генераторы и Python-ридер удалены. Реальные данные в `data/era5` сохранены.

## Архив и загрузки на сайте

В **Скачать данные для карты** доступны три архива. Файлы сохраняются в исходном
NetCDF или GRIB без перекодирования и перезаписи значений.

| Выбор | Файлы |
|---|---|
| Amazon S3 · NCAR ERA5 | NetCDF4 с LSP, обычно половина месяца на файл. Оси: forecast_initial_time, forecast_hour, latitude, longitude. |
| Google · ARCO-ERA5 | Суточный CF-NetCDF с lsp(time, latitude, longitude). Читаются NetCDF3 и NetCDF4, включая int16 с scale_factor/add_offset. |
| Copernicus CDS · ERA5 | Суточные запросы `reanalysis-era5-single-levels`, `large_scale_precipitation`, все 24 часа UTC, весь мир, `data_format=grib`, `download_format=unarchived`. |

Для CDS введите API-токен в поле под выбором архива. Ключ сохраняется между запусками
в `.meteo-settings/cds-token.bin` внутри папки данных. На Windows используется DPAPI
текущего пользователя; на Linux файл создаётся с правами 0600. Служебная папка исключена
из Git. Ключ не возвращается через API и не попадает в квитанции/журналы загрузок.
Пустой токен удаляет сохранённую копию. Перенесённая на другую учётную запись Windows
копия DPAPI не расшифровывается: в этом случае поле ввода открывается заново.
Для постоянной настройки используйте переменную окружения `CDSAPI_KEY` либо `Era5__CdsToken`.
Условия ERA5 необходимо предварительно принять вручную на странице набора CDS.
Кнопка применения подтверждает сохранение токена; доступ к CDS проверяется при отправке запроса.
После применения блок сворачивается до статуса и кнопки с карандашом. Карандаш открывает
поле замены, «Отмена» возвращает компактный вид без изменения сохранённого токена.
Первый и второй архивы подписаны `NC`, третий — `GRIB`; подписи строятся из форматов API.
Страница `/downloads` отдаётся с `Cache-Control: no-store`; в рабочем проекте HTML
читается непосредственно из `web`, в отдельной публикации — из `Assets`.
HTTP 401 отмечается как ошибка токена. Если CDS отвечает `required licences not accepted`,
показываются отдельная причина `licence_required` и ссылка на раздел `manage-licences`
самого набора ERA5. Общие условия CDS в профиле и условия конкретного набора — разные
согласия. Другие отказы HTTP 403 показываются отдельно, без утверждения о причине.

Список CDS — план суточных запросов, размер `bytes=0` означает, что точный размер пока неизвестен.
`estimated_bytes` вычисляется по медиане размеров уже скачанных суточных GRIB этого же продукта
и отображается со знаком ≈. Оценка не используется для процента или контроля полноты файла.
В очереди показываются неопределённый индикатор, прошедшее время и ссылка на очередь CDS;
после подготовки — точный размер, переданные MB и процент. Опрос во время передачи — каждые 500 мс.
Последние шесть суток исключены с учётом задержки публикации ERA5T; CDS может отклонить
запрос, если фактическая публикация задержалась. После отправки интерфейс показывает
очередь CDS и подготовку результата. Номер задания сохраняется в `.cds-request.json`;
остановка приостанавливает локальное ожидание/передачу, а подготовка на стороне CDS
может продолжаться. Повторная загрузка подключается к тому же заданию, включая после
перезапуска приложения. Активные ключи запросов сохраняются в `.meteo-settings/cds-queue.json`
и автоматически продолжаются после перезапуска при наличии сохранённого токена.
Ручное нажатие «Остановить» исключает запрос из автоматического продолжения.
Для истёкшего/ошибочного задания доступна повторная отправка.
Источники протокола: [CDS API](https://cds.climate.copernicus.eu/how-to-api),
[официальный клиент ECMWF](https://github.com/ecmwf/ecmwf-datastores-client).

Под выбором архива — прямая ссылка на выбранное хранилище. Год и месяц
фильтруют каталог; «Скачать отсутствующие» ставит файлы в очередь.
У завершённых файлов остаётся одна кнопка «Скачано», без повторного статуса.
Панель самостоятельного импорта временно убрана из интерфейса.

Каталог ARCO читается из открытого Google Cloud Storage с фильтром только
`large_scale_precipitation/surface.nc`, пагинацией и закреплением версии объекта.
Отсутствующие дни можно скачать из второго архива. Все файлы содержат ERA5 LSP;
суммарные осадки и другие продукты к нему не подмешиваются.

В CF-NetCDF ERA5 время обозначает конец предыдущего часа. Читатель согласует
его с общей шкалой карты и распаковывает значения в памяти, сохраняя исходный
файл на диске неизменным. Анимация последовательно читает часы Google-файла.
После скачивания перейдите на карту: доступные периоды обновляются автоматически.

Загрузка выполняется на C# в папку `Era5:Data`; для пути к одному файлу — рядом
с ним. Для отображения всех загрузок задавайте папку. До 512 заданий в очереди,
два скачивания одновременно. Учитываются свободное место и резерв 512 MiB.
HTTP Range/If-Match и `.partial`/`.download.json` позволяют продолжать
прерванную загрузку. При изменении ссылки/размера результата частичный файл скачивается заново.
Если хранилище CDS не поддерживает Range, результат безопасно скачивается целиком с нуля.
Полный файл проверяется NetCDF-C либо GDAL и атомарно переименовывается
в `.nc` или `.grib`; существующий файл не перезаписывается. Для CDS дополнительно проверяются
все 24 часа выбранных суток и сохраняется квитанция с размером. Отметка «Скачано»
сохраняется после перезапуска. API-токен отправляется только CDS API; ссылки и
перенаправления результата ограничены официальными HTTPS-хранилищами ECMWF/Copernicus.

Кнопка **Удалить** есть у скачанных файлов в каталоге источника.
После подтверждения удаляются файл и его служебные метаданные. Активные читатели
предварительно закрываются, кеш и индекс сбрасываются. Удалённые часы исчезают
из покрытия, а тот же файл можно скачать заново. API принимает только
непрозрачный идентификатор из списка, не произвольный путь; файлы вне папки
архива и переходы через символические ссылки удалению не подлежат.

API:

- `GET /api/archive/settings` — варианты Amazon/Google/CDS, ссылки и `cds_configured`.
- `POST /api/archive/cds-token` — JSON `{ "token": "API-токен" }`, пустая строка очищает токен.
- `GET /api/archive/files?year=2023&month=1&source=amazon|google|cds` — каталог;
  по умолчанию Amazon. Ответ содержит имя, формат NetCDF/GRIB, поставщика, размер,
  состояние и `local_id` уже имеющегося файла.
- `POST /api/archive/download` и `/cancel` — JSON `{ "key": "ключ каталога" }`.
- `GET /api/archive/local` — локальные файлы с `id`.
- `POST /api/archive/delete` — JSON `{ "id": "идентификатор локального файла" }`.

Для тестов используются `Era5:ArchiveBaseUrl`, `Era5:ArcoBaseUrl` и `Era5:CdsBaseUrl` на loopback HTTP.

В верхней строке карты между «Осадки · LSP» и кнопками PNG/JPEG
отображается «Кадры файла: имя · формат»; подпись обновляется
вместе с показанным часом. В правом верхнем углу — PNG и JPEG. Время кадра
показано только рядом с ползунком. Кнопка полного экрана в строке управления
разворачивает карту и управление вместе, сохраняя пропорции географической сетки.
Повторное нажатие или Esc возвращает обычный вид. При запрете Fullscreen API
во встроенном браузере блок разворачивается в пределах окна.
Экспорт использует белый фон, чтобы подписи читались и в JPEG.

## Настройки

В `dotnet/MeteoBridge.Era5/appsettings.json`, секция `Era5`:

| Настройка | По умолчанию | Назначение |
|---|---:|---|
| Data | data/era5 | Путь к реальным данным относительно корня проекта |
| Workers | 2 | Число отдельных процессов чтения, 1–4 |
| LookaheadCycles | 3 | Сколько следующих циклов готовить, 0–6 |
| CacheCycles | 6 | Лимит готовых и ожидающих циклов, 1–12; не меньше LookaheadCycles + 1 |
| MaxCells | 100000 | Максимум отображаемых точек в одном кадре, до 1000000 |
| MaxReadMiB | 256 | Максимальный размер исходного 12-часового float32-блока на worker |
| Bbox | [-180,180,-90,90] | Необязательная область west, east, south, north |

Изменения применяются после перезапуска сервера. Параметры также принимаются
через `--Era5:Workers 3` и другие ключи стандартной конфигурации ASP.NET Core.

## Поток обработки

1. Индексируются только координаты и время всех файлов; поля осадков не сканируются.
2. Первый запрошенный цикл получает приоритет, за ним ставятся три следующих.
3. Два процесса параллельно читают разные циклы. Внутри каждого процесс работает
   с NetCDF последовательно: библиотека NetCDF-C/HDF5 не считается потокобезопасной.
4. Исходный цикл читается одним непрерывным hyperslab, соответствующим native chunk
   текущих NCAR-файлов. Затем выбираются координаты карты, метры переводятся в мм.
   Флаги пропусков, fill values, valid range, отрицательные и нечисловые значения
   становятся NaN. Почасовые amounts не вычитаются друг из друга.
5. В браузер передаётся только один час в little-endian float32. Браузер держит
   до 12 кадров и готовит следующие восемь, выполняя до двух запросов одновременно.
6. При переходе к следующему циклу окно предзагрузки сдвигается даже при попадании
   кадра в кеш браузера. При перемотке браузер отменяет устаревшие запросы, сервер
   отменяет ненужные незавершённые циклы. Занятый отменённым чтением worker
   завершается и при следующем запросе запускается заново.

Архив целиком в память не загружается. При стандартной сетке 181×360 шесть
готовых циклов занимают до 18.8 MB данных в серверном кеше; у каждого worker
дополнительно есть исходный блок (~50 MB), native chunk cache (64 MiB) и .NET runtime.
MaxReadMiB ограничивает один массив, а не полный RSS дерева процессов.
С повышением Workers и MaxCells растёт потребление памяти. Дисковая пропускная
способность и сжатие могут ограничивать выигрыш от дополнительных workers.

Каждый час хранит список всех подходящих источников. Начальный порядок чтения:
**Amazon S3 · NCAR ERA5 → Google · ARCO-ERA5 → Copernicus CDS · ERA5**.
Панель «Приоритет чтения файлов из архива» меняет порядок этих трёх архивов
перетаскиванием строк или стрелками. При перетаскивании линия показывает место вставки;
порядок сохраняется только после отпускания строки в новом месте. Отмена перетаскивания ничего не меняет.
Перестановка сразу сохраняется и применяется, без кнопок применения и сброса.
Amazon и Google имеют независимые приоритеты, хотя оба поставляют NetCDF.
Внутри архива файлы сортируются по формату, полному пути и времени цикла.
Принадлежность определяется по именам загрузчика; для переименованных NetCDF
распознаются поддерживаемые схемы NCAR ds633.0 и ARCO CF LSP.
Прочие локальные файлы дополняют данные после трёх архивов в порядке NetCDF → GRIB → GeoTIFF.
Настройки хранятся в `.meteo-settings/map-priority.json` как порядок `amazon`, `google`, `cds`,
без копирования/изменения данных. Новые файлы автоматически наследуют приоритет архива.
Старый список идентификаторов отдельных файлов при чтении заменяется начальным порядком архивов.
POST принимает только перестановку трёх известных архивов. Изменение приоритета пересоздаёт индекс и кеш,
меняет manifest SHA256 и перерисовывает выбранный час без перезагрузки страницы,
сохраняя диапазон, масштаб и режим развёрнутой карты.

- `GET /map-archive/priority` — три архива в порядке чтения, формат, количество и объём их файлов.
- `POST /map-archive/priority` — JSON `{ "order": ["google", "amazon", "cds"] }`; `[]` также принимается для совместимости и возвращает начальный порядок.

Чтение резервных файлов прекращается после заполнения всех ячеек. Валидный ноль
из `.nc` имеет приоритет так же, как положительное значение. Если источников нет,
остаётся NaN: соседний час вместо наблюдения не подставляется.
Изменение размера, mtime или описания импорта отклоняется и при обращении к кешу.

## Три формата и согласование

| Формат | Требования и время |
|---|---|
| NetCDF `.nc` | NCAR ERA5 LSP ds633.0 либо CF-NetCDF ERA5 `lsp(time, latitude, longitude)` с `standard_name=lwe_thickness_of_stratiform_precipitation_amount`, в метрах. Уже почасовые amounts, без вычитания соседей. |
| GRIB `.grib/.grb/.grib2/.grb2` | LSP/NCPCP. Автоматическое время: GRIB1 ECMWF, таблица 128, параметр 142, поверхность, `timeRangeIndicator=4`; GRIB2 PDT 4.8, один интервал накопления. Для других файлов без достаточных метаданных задайте первый час, единицы и накопление вручную. |
| GeoTIFF `.tif/.tiff` | Географическая привязка с CRS; каждый канал соответствует следующему часу. Первый час UTC, единицы и накопление задаются при импорте. |

Для GeoTIFF также можно встроить атрибуты `METEO_START_UTC`, `METEO_UNITS`,
`METEO_QUANTITY=large_scale_precipitation`, `METEO_ACCUMULATION=hourly|cumulative`.
Настройки импорта сохраняются рядом с файлом в `.meteo.json`; исходный файл
не переписывается. Допустимые единицы — `m`, `mm`, `kg m-2`.
При ручном времени оно относится к первому каналу LSP; остальные каналы LSP
должны следовать с шагом ровно час. Другие параметры GRIB пропускаются.

Накопления GRIB с общим началом вычитаются только при наличии предыдущего
накопления, заканчивающегося ровно на час раньше. Большой интервал без такого
предшественника отклоняется. В ручном режиме `cumulative` первый канал должен
содержать накопление за первый час, последующие — накопления от того же начала.
Отрицательные разности, пропуски и сбросы накопления становятся NaN и могут
заполняться следующим источником. Температура, суммарные осадки и скорости
осадков автоматически с LSP не объединяются.

Индекс строит единую сетку из координат всех источников в выбранной области,
ограниченную `MaxCells`. Географические сетки в градусах с нулевым меридианом Greenwich
читаются с исходными центрами и размерами ячеек, включая сферическую сетку ERA5;
GDAL приводит проецированные растры к WGS84, затем все источники
семплируются на эту сетку билинейно. Пропуск среди необходимых соседей не
превращается в ноль; за пределами покрытия нет экстраполяции. Интерполяция
предназначена для карты и не гарантирует сохранение интеграла осадков по площади.
Сетка, положение камеры и цветовая шкала не меняются при смене источника.

На соседних часах при воспроизведении смена набора файлов сопровождается
коротким визуальным переходом (до 160 мс). Он включён автоматически и учитывает
системную настройку reduced motion. Перемотка и пауза показывают исходные значения
выбранного часа; промежуточные значения не попадают в API или кеш данных.
В верхней строке карты перечислены файлы, форматы и, при объединении, доля заполненных
ячеек от каждого источника. Заголовок ответа `X-Frame-Sources` содержит
URI-encoded JSON с `Name`, `Format`, `Cells`.

## Импорт локальных файлов

Панель импорта временно убрана со страницы архива. Ниже описан серверный API.

Раздел `/downloads` принимает несколько файлов через выбор или перетаскивание.
Для каждого можно проверить настройки и прогресс; кнопка «Добавить все»
запускает подготовленные загрузки. Сервер принимает до двух одновременно,
не более 8 ГиБ на файл. Файл сначала сохраняется в исключённую из индекса
папку `.pending`, проверяется читателем, затем целиком переносится в `imports`.
Одноимённые файлы не перезаписывают друг друга. Ошибка или отмена удаляет
только временные файлы. Вернитесь на карту для обновления индекса.

`GET /api/archive/local` перечисляет локальные файлы.
`POST /api/archive/import?name=FILE` принимает бинарное тело файла.
Для ручных метаданных: `metadata=manual&start_utc=2023-01-01T06:00:00Z&units=mm&accumulation=hourly`.
Для отображения всех импортов `Era5:Data` должен указывать на папку.

Описание драйверов: [GDAL GRIB](https://gdal.org/en/stable/drivers/raster/grib.html),
[GDAL GeoTIFF](https://gdal.org/en/stable/drivers/raster/gtiff.html).
Исходный каталог: [Google ARCO-ERA5](https://github.com/google-research/arco-era5),
[суточные single-level исходники](https://github.com/google-research/arco-era5/blob/main/raw/daily/era5_sl_hourly.cfg).
На Windows для native NetCDF с кириллицей используются короткие пути NTFS;
при недоступных коротких именах используйте каталог с ASCII-путём.

API `/map-archive/catalog`, `/range`, `/frame` совместим с прежним viewer.
Дополнительно доступны `/prefetch`, `/metrics`, `/health` и `/grid`.
`end_hour` ограничивает подготовку выбранным периодом, конец не включается.
Идентификатор архива передаётся как `manifest_sha256`. Ошибки выбора дают 422,
смена идентификатора — 409. Сервер предназначен для локального просмотра
и принимает только loopback-соединения.

```powershell
uv sync --frozen
dotnet build MeteoBridge.sln -c Release
uv run --frozen pytest -q -p no:cacheprovider --junitxml=artifacts/validation/site-only-full.xml

```

Тесты сами запускают временные C#-серверы и локальный контрольный NCAR-каталог.
Работающий основной сервер и доступ к интернету им не нужны.

## Исторические замеры

На этой машине проверены 48 реальных кадров (3 127 680 значений): float32
и позиции NaN совпали точно. Переходы Python между циклами заняли 2.78–3.03 с,
C# с предзагрузкой — 4.16–8.75 мс; первый кадр C# — 581 мс. Зафиксированы два
одновременных worker и серверный кеш 18 766 080 байт. Это результат данного
запуска с неконтролируемым кешем ОС, не гарантия задержек на другой машине.

Тесты создают маленькие контрольные NetCDF: это тестовые fixtures, а не новый
синтетический набор для визуализации. Проверяются переходы между файлами,
пропуски, маски, дубликаты, изменение исходника, границы выбранного периода,
точность, параллельность и повторное использование кеша.
Дополнительно проверяются занятый порт, повторный запуск, каталог NCAR,
отмена, докачка по Range/ETag, статусы имеющихся файлов и обновление индекса.
